# 倪海厦辨证研究引擎 v0.1

本地 Windows 医师研究工作台。当前是工程验证版：真实课程资料可检索、回到原件；病例事实可与原文研究条目逐项对照；已审核规则由确定性核心执行。**当前尚未完成临床有效性验证，不能直接作为接诊或处方依据。**

## 本机打开

双击 `start.cmd`，或运行 `powershell -NoProfile -ExecutionPolicy Bypass -File start.ps1`。地址为 `http://127.0.0.1:8765`，仅监听本机。服务隐藏运行；停止使用 `powershell -NoProfile -File stop.ps1`。

本机已登记用户提供的7份PDF、1935个物理页，原件与哈希保存在本工程的 `data/`。原始提取均保留待校核状态。另有9条真实来源研究卡及9个待医师定义的规则草稿，均未发布为临床规则；2条明确标注的合成规则仅供算法测试。测试病例代号以 `SIM-` 开头。

源码包不包含课程PDF、病例、凭据或运行数据库。解压到新目录时：准备Python 3.11和Node 22.19以上，运行 `setup.cmd` 安装固定依赖，再运行 `start.cmd`。随包包含前端生产构建；如要开发界面，在frontend运行 `npm ci` 和 `npm run build`。

## 五项核心如何使用

1. **知识库**：资料与溯源页可检索全部1935页，查看9条方证/加减研究卡。原典、倪氏讲解归纳、AI整理和待审状态分别显示；《黄帝内经》文件的解说归属未确认，不能仅凭文件名归倪。
2. **原文溯源**：打开具体物理页，直接看PDF原件图像及原始提取；PDF链接附物理页锚点。订正另存，创建证据需已校核页及真实连续引文。物理页与印刷页分别记录。
3. **方证对照**：录入当次已核实四诊事实，明确存在/否定/未知/冲突、本人/家属/其他主体及当前/既往。文献候选列出支持、反证、未知和鉴别问题，按来源页序展示，不作优先选方或概率排序。
4. **加减规则**：研究卡保留原文明确的增减记载；真正执行的规则绑定基础方版本、必要/排除条件、动作、炮制、单位及来源。研究草稿的必要条件是不可发布的占位项，医师须重新定义，不能直接将支持症候全当必要条件。
5. **算法分析**：确定性核心无网络；三值逻辑、反证/未知/冲突处理、加减冲突、同身份/单位/计量基础的Decimal合计、风险覆盖和不可变快照可独立测试。断网不影响已有原文和规则。

接诊页“文献对照示例（合成）”用于验证真实条文对照，“算法边界示例”用于验证合成规则；均不代表真实患者或医学验证。修改事实后旧分析失效，采用旧版本会被服务端拒绝；复诊从空事实开始，历史记录另列。

## 合作医师审核

用户已指定由合作执业中医师负责专业审核。先使用配套《首批方证与加减_医师审核包.md》，逐条核对引文和适用范围，确定必要条件、支持条件、排除/鉴别、加减动作、逐味炮制/剂量/单位及煎服依据，并给出代表病例和反例。

工作台规则页支持文本、语义、临床三级审核及发布/撤回；本地署名不验证执业资质。点选审核不是临床有效性证明。已有发布版本不可覆盖，修订使用新id/版本；撤回或证据订正不改写旧快照，但阻止旧依赖继续用于当前判断。

9条研究卡由AI根据PDF图像整理，尚未经过医师逐字校勘；经典“或”项未当成共同必要条件。不结构化未核实药量，不自动古今换算。其他书目目前为页级资料，尚未全部转为结构化方证、医案或安全规则。

## 模型接口

在“模型与备份”设置API基址、模型ID和密钥。此版本固定Pi AI 1.3.0，只支持已实现的OpenAI兼容Chat Completions协议；API基址如 `https://供应商/v1`。不运行编码Agent工具，不调用终端或编辑文件，不使用环境/默认文件中的账号认证。

密钥由当前Windows用户DPAPI保护，不返回前端、日志或备份。默认禁外发。连接测试仅发固定合成文本；病例补充须启用通道、许可外发并确认本次发送范围。发送仅含限定结构化事实和规则状态，病例代号、主诉、备注及事实原始描述不发送；资料片段另需许可。结构化字段仍属于健康信息，真实使用前须确认接收方和处理依据。

已用本地HTTP/SSE测试成功、断流、取消、错误、非法引用、输入变化与持久追溯；**没有真实供应商凭据，未完成真实模型调用或套餐OAuth。** 取消不保证远端立即停止计费。模型结果仅补充解释，结构/引用ID检查不等于医学内容审核；过期结果仅供历史查看。

## 备份与恢复

设置页用至少12字符口令下载加密备份。内容是数据库一致快照、该快照登记的全部原件和哈希清单；不含模型凭据。缺失或损坏原件会拒绝备份。当前上限512MiB（含清单），口令不能找回。

恢复到新建或空目录：

```powershell
python scripts/restore_backup.py 'D:\backup.tcmbak' --destination 'D:\tcm-restored'
```

工具交互输入口令，验证认证加密、路径、文件哈希、数据库及原件完整性；不覆盖非空目录。用恢复数据启动：

```powershell
powershell -NoProfile -File start.ps1 -DataDirectory 'D:\tcm-restored'
```

先停止原服务；同端口只运行一个实例。恢复后重新配置密钥。真实病历的OS访问控制、磁盘加密和机构数据制度仍未验收，当前仅用模拟病例。

## 开发与验证

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
cd frontend
npm ci
npm test
npm run build
cd ../ai-bridge
npm ci --ignore-scripts
npm test
```

本地审计文本导入和研究卡导入为受信CLI，不暴露任意文件路径给浏览器：

```powershell
python scripts/import_audit.py 'manifest.json' --data-dir data
python scripts/import_research.py 'research-seed.json' --data-dir data
```

新机器可通过工作台重新上传同哈希原件后，导入配套研究条目JSON。研究条目数据有意与源码包分开；不得将其等同原始课程或已审核规则。

## 当前未完成

尚缺合作医师的实质审核、现代药物安全资料覆盖、完整药物/剂量/服法知识结构化、全书/医案语义校勘与跨页关系、经验证的完整临床规则集、独立真实病例评估，以及真实用途、数据和适用监管条件确认。模型待核事实提取确认也尚未实现，当前四诊由人工录入。

因此本版的可运行、可测试、可追溯，不等于临床可用。目标是让上述审核结果可以变成明确、可核对和可调整的引擎输入，继续朝限定接诊辅助推进。
