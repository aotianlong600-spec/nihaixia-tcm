# OAuth 登录排障说明

## 当前实际故障

原生 OAuth 流程在凭据校验成功之后失败，进程退出码为 `0xC0000409`（Windows原生进程快速失败状态）。该轮已有完整凭据返回，确认还发生了原生运行时退出崩溃。退出码本身不说明所有授权失败的原因；随后遇到的OpenAI网页403、HTML响应或网络中断应另行判断。

私有的 Node 运行时已被固定为 `24.22.2`，并包含官方修复（nodejs 61999）。请使用仓库内固定的这份运行时，不要改用系统 PATH 中的其它 Node 版本。

### 登录成功但问诊没有 AI 回复

先看界面错误提示，它现在会区分以下原因：

1. `当前未选择模型配置` 或 `请在模型设置中启用接口并允许发送必要症状和书证`：到“模型与数据”选择配置，并勾选启用及允许发送。
2. `Codex账号当前额度或频率受限`：账号返回 429；等待提示的分钟数后重试，或临时切换到可用的 API Key 配置。切换只影响新请求。
3. `当前Codex模型不接受本次推理参数`：模型桥按 SDK 模型目录发送参数，不再给不支持 `off` 的模型硬塞 `reasoning.effort: none`。若仍出现，先更新 `ai-bridge` 依赖。
4. `模型请求超过本机等待时限` / `模型流式响应未正常结束`：可能是网络或上游中断，重试即可；反复出现时核对额度与网络。
5. `本机模型桥拒绝了请求参数`：检查配置中的模型 ID、地址和密钥；日志会记录安全的字段名，不记录密钥或问诊正文。

桥接层只把 HTTP 状态和机器可读的 `code/param/type` 传给工作台，不转发供应商原始错误正文，避免错误信息回显输入或凭据。真实 Codex SSE 响应可能没有 `Content-Type` 头，桥只拒绝明确非 SSE 的类型；无法解析出完整终止事件时仍失败关闭。

## 容易混淆的概念

以下机制彼此不同，不能相互替代或等同：

- 浏览器回调（browser callback）
- 短设备码（short device code）
- 手动回调（manual callback）
- 请求中出现的 `request_id` / `accountId` 属于标识字段，**不是**授权码（auth code）。

## 配置损坏与密钥清理

配置损坏时程序会拒绝使用，保留文件，不在读取请求中自动清空。请先停止工作台，单独保管本机的模型配置文件和加密密钥目录，优先恢复同一时间的配置及匹配密钥。医学数据库备份不包含这些模型凭据。

如果没有可恢复的模型配置，可在本机保留并重命名损坏的 `model-profiles.json` 和旧 `model-config.json`，再启动工作台重新配置；需要输入对应密钥或重新授权。不操作病历、原件或医学数据库。损坏或不属于当前Windows用户的Codex授权，也可由本人点击“清除不可用授权”后重登。

更新/删除若提示加密文件未清理，配置状态以界面显示为准，未清理的文件不会被新配置引用；请在本机检查文件权限后处理。程序不会在读取配置时自动删除密钥备份。

切换API地址或从Codex切回API时，如原配置保有API密钥，需要重新输入对应密钥。选择配置仅影响新请求；删除当前配置后不会自动改用另一个提供方。Codex配置目前共用一个授权账号，删除配置与退出共享账号是两个操作。

以上两项由其它改动独立实现，本文档不声明其已完成或已验证。
