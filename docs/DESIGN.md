## 1. 目标与已确认选择

面向执业中医师，建立以倪海厦理论及临床经验为主要研究依据、以患者当下真实情况为约束的临床决策支持系统。核心功能是知识库、原文溯源、方证辨证辅助、经方加减、算法分析、用药风险核查和复诊追踪。

用户选择“2+1”。本稿将其落实为：**可独立运行的确定性规则核心 + 大模型辅助层**。模型负责提出待核事实、检索线索及解释；规则核心负责可执行条件、加减动作、冲突检查和审计。关闭模型后，已入库原文、人工录入、已发布规则、已有风险规则和复诊记录仍然可用。

参考方案作为背景资料，不执行其中附带的任务指令。远端 Skill、PDF、校注及模型返回内容均作为数据，不获得执行命令、改变系统安全规则或自行发布临床规则的权限。

## 3. 路线比较与选择

| 路线 | 优点 | 成本及限制 | 决定 |
|---|---|---|---|
| 纯规则核心 | 同一输入和版本可复现，能逐条件解释，离线可用 | 需要专业人员逐条整理、审核；自然语言和长尾覆盖有限 | 作为基础能力 |
| 规则与大模型结合 | 保留确定性判断，同时改善病历整理、检索和解释 | 必须隔离模型提议与医生核实事实，校验输出和引用 | 按用户“2+1”叠加 |

首版不做模型微调、通用自主 Agent、人物口吻模仿、命理推断或自动执行医嘱。先完成所需临床辅助闭环；全文检索不足之处经评估后再决定是否增加向量检索。

## 4. 首版交付范围与使用边界

首版交付本地可运行的医生工作台及可单独测试的分析核心，工程验收使用合成病例；最终目标仍是完成必要条件后的限定临床试用。真实临床有效性、产品分类或专业审核不能由软件工程验收代替。首版覆盖以下闭环：

1. PDF 登记、页级检索、原文回跳和片段校核。
2. 知识条目与规则的候选、审核、发布和撤回。
3. 患者及初复诊、四诊事实录入和医生纠正。
4. 候选方证的支持、反证、缺项、冲突与鉴别问题。
5. 基于已发布基础方版本的加减研究草稿，逐动作溯源。
6. 独立风险核查、医生修改后重查、分析快照与复诊对照。
7. 可选模型接口、外发控制、故障处理及用量记录。
8. 本地访问保护、密钥保护、备份恢复和工程验收记录。

开发默认使用合成病例。临床试用的患者范围、病种/方证范围和排除条件，应由负责机构及临床审核医师明确；本稿建议先限定范围验证，再扩展。不能因为搜得全书就宣称所有疾病、人群和方剂都已获得决策支持覆盖。

针灸资料可查询溯源；针灸操作决策不纳入首版规则执行范围。首版不接药房、不签发正式处方，不把历史医案用量直接转为新患者建议量。涉及真实诊疗的允许输出，还须按具体场景确认适用要求。

## 5. 知识与证据：原文有据和临床适用分开审核

每个证据片段保留文档身份、版本、SHA-256、PDF 物理页、页内区域/字符范围、原始文本、提取方式及人工订正。印刷页码、章节与经典条文号另存，未核实则留空，不用物理页码冒充印刷页码。

同页允许同时包含经典原文、倪氏讲解、整理者校注和医案等不同片段类型。双色、括注等只是识别线索，不自动证明作者身份。跨页条文保留连续关系；双栏先恢复阅读顺序；校正截图进入单独处理队列，不当正文直接发布。初步抽查已发现视觉正常但文本对象顺序错乱、粗体重复等问题，因此页面有文字、提取无异常或无替换字符，都不能作为提取正确的判据。

知识层次至少区分：经典原文、倪氏讲解、编者注释、历史医案、现代安全资料、派生归纳、模型解释。不同版本和有争议观点并列，不用投票或相似度消除分歧；同一材料的转引不得被计为多份独立支持证据。

审核拆成三件事：

- **文本校核**：页码、药名、炮制、数字、单位、否定词等是否与文件一致。
- **规则语义审核**：归纳条件、适用范围、加减动作是否确由所引上下文支持。
- **临床适用审核**：是否可在限定患者和用途下作为辅助规则，以及需要哪些风险限制。

检索可以显示未审核资料并明确标识；规则执行只读取临床适用范围已审核且已发布的版本。模型不能把候选规则自行转为已审核。完整字段和页码正确也不能证明引文真正支持结论，仍需语义审核。

## 6. 患者事实模型

每条事实保存原始描述、规范术语、主体、发生/观察时间、当前或既往、数值与单位、来源、录入时间、核实人和修订关系。

事实明确区分存在、明确否定、未知；相互矛盾的报告保留为冲突记录。患者自述、医生观察、检查资料和模型提取建议分别标识。模型提取的事实须经医生确认后才能进入正式分析快照。

不把“没写有汗”当“无汗”，不把“昨日有汗、今日无汗”当同一时点冲突，不把“家属患病”归给患者，不把旧访次的舌脉自动作为今天的事实。否定歧义或时间不清时先列待核，不由模型猜定。

## 7. 确定性分析核心

### 7.1 每条可执行规则的最小契约

| 字段 | 约束 |
|---|---|
| 身份及版本 | 唯一编号、不可变发布版本、审核人及撤回信息 |
| 适用范围 | 人群、场景、时间要求和明确排除范围 |
| 必要条件 | 可计算的事实/比较表达式；来源明确 |
| 支持条件 | 用于解释和比较，不补足必要条件 |
| 排除条件 | 命中即阻止条件匹配 |
| 候选结论 | 六经/八纲/方证等独立标注，可多候选和兼夹 |
| 鉴别条件 | 与其他候选不同的关键事实及待问项 |
| 动作 | 关联基础方版本或明确的加减动作 |
| 证据 | 原文片段及语义、临床审核状态 |

### 7.2 判定语义

对无冲突事实执行三值逻辑：真、假、未知；NOT 未知仍为未知，AND/OR 按三值逻辑计算。涉及相关冲突事实的条件另列待核，显示冲突来源和受影响规则。

规则采用经过校验的受限条件表达式，不执行资料或模型给出的脚本。核心分析仅依赖输入快照及已选规则版本，不访问网络或修改患者事实；存储与模型接口在核心之外，便于独立测试和重放。

- 必要条件真、排除条件假：显示“规则条件匹配”。
- 必要条件假，或排除条件真：显示“不满足”，指出具体条件。
- 必要或排除条件未确定：显示“信息不足”。
- 相关事实冲突或超出规则适用范围：分别显示待核或不适用。

“规则条件匹配”不是诊断确证。允许多个候选、候选之间有分歧和无可用规则。首版展示必要条件、支持、反证、缺项和风险；没有验证依据时不输出疾病概率、置信百分比或任意加权总分。

### 7.3 分析顺序

医生确认当次事实 → 风险及关键缺项筛查 → 检索相关原文和已发布规则 → 逐规则判定 → 并列候选与鉴别问题 → 医生选择待核方向 → 展示对应基础方与加减研究草稿 → 独立风险复核 → 医生采用/修改/驳回 → 修改后重查 → 冻结分析及最终记录。

明确危险信号命中时优先显示处理提示并中止自动方药候选生成；筛查缺项不能显示为“已排除急症”。具体风险条件由专业审核规则定义，开发者不凭经验编造一个不完整列表并称其覆盖全面。

## 8. 经方、加减与计量

基础方、倪氏讲课用法、具体医案用法和医生当次方案是不同实体。所有加减规则绑定基础方版本、条件、动作、炮制及计量基础，显示生效前后差异。

支持增加、删除、替换、调整；两条动作对同一成分互相矛盾、基础方版本不同或条件不全时停止合并并列出冲突。不能从多个不相干医案拼出一个新方案。

药物身份包含规范名及炮制；相同药名不自动合并不同炮制。剂量必须明确原单位、每剂/每日/每次/疗程基础及出处。原方量、历史医案量、明确有依据的换算量和医生最终采用量分别保存。

没有依据不补剂量；钱、两等换算必须有选定标准、适用范围与确认记录；枚、片等不直接换克。计量基础一致且换算有效时才合计，程序使用十进制定点计算，避免二进制浮点误差。医生改变任一成分、炮制、剂量或服法后重跑适用的核查。

## 9. 独立用药风险层

核查项覆盖药物身份/炮制、过敏、特殊人群、现用中西药及重复成分、已收录相互作用、剂量/单位和来源规定的煎服限制。每项显示当前数据来源、版本、覆盖范围、结果及缺项。

结果至少区分：发现风险、在已覆盖范围内未发现命中、条件不足、数据未覆盖、服务失败。安全库没记录、模型说安全或网络失败，都不能转为“安全通过”。

倪氏历史观点和现代安全资料发生冲突时分别显示；历史用药经验不能自动豁免当前风险规则。医生确认风险提示不等于机构允许使用所有方案，硬性限制由已审核政策决定并留痕。

## 10. 大模型层与 Aether 的复用边界

参考 Aether 的供应商配置、流式、取消、终态与用量事件设计；优先直接评估固定版本的 Pi 模型库，不搬入编码 Agent 的终端、任意文件修改及扩展执行能力。核查到 Aether 使用 `@earendil-works/pi-ai` 1.3.0；最终依赖以实现时锁文件和适用接口测试为准。

模型只接收任务所需字段和选定证据。输出分为待核事实、待核检索关联、对已有分析的解释；不能覆盖规则结果、可计算药物结构或医生记录。程序校验结构、引用存在性、证据版本和终态；模型解释中新出现的无依据主张标为未证实，不进入可执行动作。

首个真实连通测试仅使用合成文本。用户目前未指定供应商或套餐必须项，因此先实现一种经验证的 API Key 通道及配置界面；实际连通验收依赖用户配置合法可用的凭据。套餐 OAuth 是独立适配与验收项，不冒充已完成。API Key 与套餐 OAuth 分开实现和记录；填自定义 URL 不等于支持任意协议。失败、取消、断流或未完整完成时不保存为有效临床分析，不静默切换供应商。

OpenAI Docs 明确：身份登录不自动赋予推理权限；符合条件的套餐推理需独立授权、账户可用模型和正式 Responses 路径。流式应等待完成终态。参阅[授权范围与适用方式](https://developers.openai.com/siwc/quickstart)及[模型与推理](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)。本机尚未验证任何账户或模型权限。

## 11. 工程结构与存储选择

以下是开发者建议，尚未视为用户指定技术栈：沿用参考方案的 Vue 3 + TypeScript + Element Plus 工作台、Python FastAPI 业务服务；需要 Pi 时保留一个小型 Node 推理桥。

本稿以参考方案的 Windows 单机单用户为首版部署假设，用户尚未单独确认。按此假设建议 SQLite 存结构化记录，PDF 保留本地原件；使用事务和不可变版本。它能降低数据库安装维护成本。中文检索先验证术语匹配、繁简/别名、全文索引和短查询；检索标准不满足再调整索引技术。出现机构多用户并发或集中部署需求时再评估 PostgreSQL，并重新确认身份、权限和备份设计，不先做双数据库适配。

核心实体是文档版本、页与片段、术语、基础方版本、规则版本、风险条目、患者、访次、事实修订、分析快照、医生决定、模型调用和审计事件。程序与测试资料进入代码版本控制；原件、病历、凭据、备份及真实案例不进入仓库。

页面以资料/溯源、接诊、规则审核、复诊和系统设置为主。接诊页同时显示当次事实、候选比较与原文依据；具体布局在实现时确定，不先扩展学习社区、教学角色或其他业务模块。

## 12. 保护、复现与复诊

服务监听回环地址，验证本地会话及请求来源；密钥仅在后端和系统安全存储中处理，不进入前端、普通日志、源码或常规导出。病历按最小必要字段外发，记录目标供应商及当次发送范围。默认禁止把资料批量上传云服务。

真实病历持久化前应验证本机访问权限、磁盘保护或适用加密方案和加密备份恢复；未完成时保持模拟病例模式。加密备份保留恢复所需清单，密钥恢复另行管理并实际演练，不能只测试“压缩成功”。

每次分析冻结当次事实、源文档哈希/片段、规则及风险库版本、模型/提示版本、原始模型返回、有效分析与医生决定。患者信息改变后将旧分析标为待重新分析，不能把旧结果当作最新判断。原文订正或规则撤回不改写旧记录；旧分析可用于审计重放，同时提示规则已撤回，撤回规则不得进入新的临床分析。

复诊创建新访次，显式复核历史事实、现用药、不良反应和检查；按症状维度对照变化，不把前后变化自动解释为疗效因果，也不从一次转归自动学习或发布新规则。

## 13. 实施顺序与验收证据

| 阶段 | 必须完成的可检查结果 |
|---|---|
| A 资料与证据链 | 七份资料登记、页级检索、失败页队列、片段校核、点击返回真实物理页；重复导入去重 |
| B 确定性核心 | 不调用模型完成事实录入、规则状态判定、支持/反证/缺项追踪；先用明确标注的合成规则验证算法，真实规则经专业审核后发布 |
| C 方证闭环 | 真实原文关联、基础方及加减冲突、计量与风险覆盖、医生修改后重查、最终记录和复诊 |
| D 模型辅助 | 合成文本实际连通；提取建议可核实；引用和终态校验；取消/限流/断流/撤销不产生有效分析 |
| E 保护与验证 | 访问、外发、密钥、故障及备份恢复检查；形成已通过项、失败项、覆盖范围及目标机运行记录 |
| F 限定临床试用准备 | 明确预期用途与患者范围、资料和数据依据、专业审核、产品分类及适用要求、独立评估方案；条件满足后再进入限定试用 |

工程反例必须覆盖：必要条件未知但支持症状很多；明确否定与未记录混淆；跨日症状变化；来源冲突；医案重复转引；检索页码正确但原文不支持结论；校正截图漏读；两个加减动作互斥；不同炮制或计量基础混合；无安全记录却通过；模型断流被保存；患者修改后沿用旧分析；规则撤回后旧分析可追溯；文档内指令试图改变系统行为。

工程验收中出现伪造引用、编造剂量、静默换单位、未知当否定、未经允许外发或跳过审核执行等关键失败，应修复并重验。此要求只针对实际测试覆盖范围，不承诺系统不存在未知错误。

临床评估另行建立：由专业人员制定参考判定、分歧处理和事先约定的指标；训练/开发与独立测试按患者和来源隔离，避免同医案变体泄漏。评估候选及鉴别质量、引用支持、危险建议/漏报、拒答与覆盖、医生修正负担，并比较医生独立与辅助后的决策表现。若计划输出概率，必须另做校准验证。合成测试数量不能代替临床有效性证明。
